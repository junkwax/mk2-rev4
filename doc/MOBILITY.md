## Jump - identical for everybody

| | value | |
|---|---|---|
| initial y velocity (`up_vel`) | 10.0 px/tick | up |
| gravity (`up_grav`) | 0.50 px/tick^2 | |
| time to apex | **20 ticks** | 366 ms |
| full airtime | **40 ticks** | 731 ms |
| jump height | **100 px** | v^2/2g |
| angle-jump x velocity | 4.0 px/tick | |
| angle-jump distance | **160 px** | x * airtime |

`up_vel`, `up_grav` and the angle-jump x velocity are single
equates shared by the whole cast - **no character jumps higher,
further or longer than any other.** Every mobility difference in
MK2 is on the ground, which is worth knowing before anyone
tunes a matchup on 'he has a better jump'.

## The hidden fighters: boss scaling, and the `secretwalk` gate

The table above is the RAW data, and in it Smoke, Noob and Jade walk
at 4.5 / 4.0 / 4.5 px per tick against 2.5 for most of the cast.
They also take 3/4 damage through `ochar_damage_table`. Both are
boss scaling - they exist to make a SECRET OPPONENT a hard fight -
and in a two-player match they simply hand one player a mobility and
a durability edge that nothing in the data pays for: Smoke and Noob
share `nj_strikes` byte for byte with the ninjas (all 32 records),
and Jade shares `fn_strikes` with the female ninjas (all 26).

The damage side was already gated by `xlate_secret` (JOY.ASM), which
applies the 3/4 only when the CPU is playing them. **`secretwalk`**
(currently **1**) does the same for walk speed, in
`decode_walk_table`: a HUMAN Smoke or Noob borrows `ft_subzero`'s
row and a human Jade borrows `ft_fn1`'s - the walk of the character
whose move table they are already using - while the CPU keeps the
boss speed.

So read the walk table above as the CPU's speeds. With the gate on,
a human plays those three at 2.500 / 2.500 / 3.125 forward.

> Verified statically, not in game: a human Smoke, Noob or Jade
> cannot be reached by any rig - character-select forcing and
> `test_mode` both fail to start the fight, and only the select
> cheat produces one. The gate is instruction-identical in form to
> the shipped `xlate_secret` and uses `get_char_long`'s exact
> indexing, and it is covered by `doc/balance.lock`.
