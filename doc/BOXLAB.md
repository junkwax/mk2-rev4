# boxlab - the public viewer, and how it stays honest

boxlab is a public repository served from GitHub Pages. It is the visual half
of the idea in [COMMUNITY_PACKS.md](COMMUNITY_PACKS.md): that document
established that *the numbers travel and the source does not*; this adds a
picture, and closes the loop so that what the public repo holds is what the
ROM is built from.

**It is not in this tree, on purpose.** It is checked out as a sibling:

```
Workplace/
  mk2-main/     <- this, private, never public
  boxlab/       <- that, public, its own git history
```

A subdirectory would have been more convenient and is the wrong shape. Two
things go wrong with it, and neither is hypothetical: `git add -A` here sweeps
it into a private commit, and `git subtree split` - the obvious way to publish
a subdirectory - keeps the *commit messages*, which in this project routinely
name source files, routines and labels. Out of the tree, there is nothing to
sweep and no history to carry.

Everything in it is generated by `tools/boxlab_export.py` from this tree.

```
python tools/boxlab_export.py                 regenerate ../boxlab/data/*.json
python tools/boxlab_export.py --check         fail if the checkout is stale
python tools/boxlab_export.py --out PATH      a checkout kept somewhere else
```

`BOXLAB_DIR` does the same as `--out`. If the checkout is missing the exporter
says so and writes nothing, rather than helpfully creating a stray directory.

## The three files

| file | what it is | rows |
|---|---|---|
| `boxes.json` | **a hitbox_pack pack.** Not a copy of the strike records - the actual file `hitbox_pack.py import --apply` reads back | 228 |
| `poses.json` | every pose as a list of RECTANGLES, plus which pose each move's box is live on, plus every defensive lane | 869 poses, 199 contacts |
| `frames.json` | startup / active / recovery / advantage, joined to the public move ids | 177 |

`boxes.json` being a real pack is the point. The site and the game cannot
drift, because they are the same file - and the check for that is
`--check`, not `hitbox_pack diff`:

```
python tools/boxlab_export.py --check
-> boxlab matches the build.
```

> **`hitbox_pack.py diff ../boxlab/data/boxes.json` does not work, and this
> document used to say it did.** The published pack is a `--public` one: every
> id in it is a *public* id (`headband/hikick`), and `hitbox_pack` only knows
> private ones (`liu-kang/hikick`), so it reports "no such move in this build"
> on all 233 rows. The vocabulary lives here, in `TABLE_WORDS` / `MOVE_WORDS`,
> which is also why the inbound direction below lives here rather than there.

## Applying what the community sends back

`public_id()` takes a private record id public. `--proposals` is the other
direction, and it is what makes boxlab *authoritative* rather than merely
honest: a proposal written by someone who has only ever seen the public data
resolves back to a strike record and is applied to the build.

```
python tools/boxlab_export.py --proposals              every open one, dry run
python tools/boxlab_export.py --proposals FILE...      just these
python tools/boxlab_export.py --proposals --apply      write them into MKSTK.ASM
```

Dry run is the default, and the output is `hitbox_pack`'s own diff - so what
you approve is what you saw. Applying reuses `hitbox_pack.apply_changes`, which
keeps the source's own formatting (`05eh` stays `05eh`, not `0005eh`), so
applying a proposal and reverting it leaves `git diff` empty.

Six ways a proposal is refused, all of them before anything is written:

| refused | why it matters |
|---|---|
| `base_digest` is not this build's | every `from` in it measures a number that has since moved |
| a `from` no longer matches | the same failure, one record at a time |
| the id is not a public id | a private id in a public file is a leak, not a convenience |
| the field is not one of the six | reactions index an animation table; a "better" value is not a bigger one |
| the value is out of range | a typo'd extra digit |
| two open proposals want different values for one field | they conflict, and merging them silently would pick one at random |

`private_id_map()` is built by inverting the mapping **over the real record
set**, not by inverting `MOVE_WORDS` symbolically. That table renames some
suffixes and passes the rest through, so two private records can land on one
public id - and a rename colliding with a passthrough would otherwise resolve a
stranger's proposal onto the wrong move and apply it. Built this way, the
collision is visible, and it fails closed.

## What is new here, beyond hitbox_pack

**Pose geometry.** `parse_strips()` in `box_align_audit.py` already had
`label -> (W, H, dx, dy)` from the .TBL sprite tables, placed the way `ani2`
places them. A strip's rectangle about the anipoint is `(-dx, -dy, W, H)`, so
the blocky figure the viewer draws is free - no pixels, exact registration.
Poses are content-addressed and deduplicated, so an id never encodes an art
name.

**The flags word, put back.** `hitbox_edit` calls the eighth strike field
`sound`; it is really the flags (`balance.lock`'s own header says so), and
`sf_squeeze` lives in it. `--public` drops that field, which would leave a
viewer unable to tell which moves squeeze - 204 of 228 do. The exporter
recovers it as a neutral `flags` map on the pack.

**Move names are opt-in too.** Every published move name must be in
`PUBLIC_MOVES` (after `MOVE_WORDS` translates it), or the export aborts. Until
that existed, a new move went out under whatever the source called it, and
nineteen ids did: trademarked names (Rain, Noob, Jade, Ermac) and the
source's abbreviations (`lk`, `st`, `hh`, `rp`, `ro`, `sc`). `validate.py`
could not see them - they are well-shaped ids. Adding a move now means
choosing its public name: what it is on screen, under the owner's handle.
Rain is `purp`, Ermac is `souls`.

**A whitelist audit, not a blacklist.** `hitbox_pack.audit` looks for the
*shape* of an assembler symbol, which is right for a file of numbers and ids.
It cannot see `LKWALK1` - upper case, no underscore. The pose data is full of
art-derived material, so `boxlab_export.py` inverts it: every string in every
emitted file must match a pattern it defines, or the export aborts. It caught
two real things on the first run - my own `excluded` keys, and
`CHARACTER_LABELS` spelling Kung Lao **"Kung Lao (hathead)"**, carrying the
source's codename for him in a field nobody looks at.

## What the exporter deliberately drops

| dropped | count | why |
|---|---|---|
| moves with no single contact pose | 7 | `inline` and `upcut_striker` handlers drive their own frames - the same scope `box_align_audit` refuses |
| `assumed` rows landing on idle art | 10 | a character who does not have the move. Publishing it would draw a stance and call it a punch |
| `assumed` rows on a boss ani table | 7 | Kintaro and Shao Kahn do not use the standard layout, so an index lookup against a cast handler is meaningless |

Contacts that survive carry a `confidence` (`table`, `handler-name`,
`assumed`) and the viewer shows it.

## The checks, and that they fail

The public side has to be checkable by CI that has never seen this tree, so
`validate.py` imports nothing and reads only the three JSON
files. `prove_validator.py` injects ten faults and asserts each is
rejected - a source symbol, an art name, a lane label, a borrowed sentence,
two prose leaks, and four structural faults. All 10 caught.

The prose cases exist because that check shipped broken. The whitelist guards
the DATA; the hand-written files - viewer, docs, the tools themselves - have
no shape to whitelist, so they get a blacklist, and the blacklist's patterns
were written with a mangled escape that compiled to a literal control
character. It matched nothing and reported "clean" on every run. Two real
leaks were sitting in `index.html` at the time. Both checks now split their
own search terms in the source (`"sq" "_punch"`), so the files that have to
name these things in order to find them are not themselves the leak.

`selftest.mjs` runs `index.html`'s **own** javascript in a stub
DOM against the committed data, rather than a second implementation of the
model that could agree with the page and both be wrong. It reproduces two
numbers `HITBOX_MODEL.md` measured off the live `f_colbox` overlay:

```
jax stance frame 5 full width      66 px    (overlay: 66)
jax stance frame 5 tested width    18 px    (overlay: 18)
```

and the lane union `-29..+40` matches `hurtbox.lock` exactly. That is the
whole extraction chain - .TBL strips, anipoint placement, bounding box,
`sq_punch` - confirmed against something measured on screen.

It also reproduces behaviour nobody put in it: `liu-kang/hikick` vs a standing
Jax connects from **24 px to 109 px**, with a front edge of 94. The near edge
is the point-blank dead zone; the far edge is 15 px past the box, because the
victim has width.

## Publishing it

The checkout has its own history and nothing shared with this one, so
publishing is `git push` from there - no split, no filtering, nothing to
scrub. Run the gate first; it is the same one CI runs:

```
python tools/boxlab_export.py                 # from here: regenerate

cd ../boxlab                                  # from there: gate, then push
python tools/validate.py
python tools/prove_validator.py
node   tools/selftest.mjs
git add -A && git commit -m "..." && git push
```

Two things to do once, when the public repo exists:

* set the Pages URL at the top of `../boxlab/README.md`
* enable Pages with the "GitHub Actions" source, so `pages.yml` can deploy

## Keeping it from going stale

`--check` compares the committed files against what this build would produce
and exits non-zero on any difference. It is the same shape as the promoters and
the locks, and it is what makes "whatever is public is what is in the ROM" true
rather than aspirational:

```
python tools/boxlab_export.py --check
```

**It ignores the provenance stamp** - `generated` and `source_commit` - and
nothing else. That is not cosmetic. Those two fields say *when* and *from
what*, not *what*, and while `source_commit` was in the comparison the check
reported all three files stale after **any** commit to this tree, even when
every byte of the data was identical. A check that cries wolf on every commit
cannot be wired into a build. The `digest` field stays in the comparison, so a
real data change still fails.

**It runs in Phase D as a warning, not a failure.** Failing the build whenever
a balance change lands before a re-export is the strictly correct behaviour and
the wrong ergonomics - it would block every iteration on a chore. The warning
names the file that drifted and says what to run; the ROM still builds. Flip it
to fatal by treating the return code the way the promoters' checks are treated
in the same function.

The checkout is a sibling repository and is not always present, so Phase D
skips the check entirely when `../boxlab` is not there.

## Not covered yet

* **Frame timing is read-only.** It is derived from `doc/frame_advantage.csv`,
  so it publishes but cannot be proposed against - timing lives in code
  immediates, not a table. Wrapping `frame_edit.py` the way `hitbox_pack.py`
  wraps the strike records is the obvious next pack.
* **Inputs.** `combo_edit.py` has 91 clean records; likely the pack after that.
* **Hurt boxes** cannot be proposed by anyone, here or privately: they are
  computed from the art. `hurtbox.lock` is what stops them moving silently.
* **Attacker animation.** The viewer draws the contact pose, which is the
  frame the box is actually live on - not the windup. Showing the whole lane
  would need part-one row data the pose export does not carry yet.
* **The loop has never run with a real outsider in it.** Every rejection path
  in `--proposals` is exercised against fixtures, and the accept path applies
  cleanly, but no proposal has yet arrived as an actual pull request. Opening
  one against a record we genuinely want moved - fork, prefill, CI, apply,
  rebuild, post the overlay screenshot back - is the cheapest way to find out
  what the write-up above is still missing.
