# Matchup matrix - what reaches whom

Generated by `tools/matchup_matrix.py`. Computed from the strike
boxes and each character's real silhouette, using the model the
collision code actually uses, and **validated against the**
**emulator** to within ~2 px on Baraka's high kick.

A hit needs the strike box to overlap the victim's hittable
column. `sq_punch` insets 3W/8 from each side, leaving W/4 centred
on him - so the column reaches **W/8 either side** of his anipoint,
and the reach of every move depends on who is standing there:

    max range = box front + W/8
    min range = box near  - W/8

## So how much does the matchup actually change?

**Almost nothing, across the normal cast - and that is the**
**finding.** The only victim-dependent term is W/8, so every move
in the game reaches 1.9 px further against hathead than against kitana.
Under two pixels. Spacing learned in one matchup transfers to
every other one, which is a good property for a tournament game
and is not something anyone had checked.

## What this does NOT cover

Projectile records. Their box rides the projectile object rather
than the fighter, so the front edge is not a reach - `stk_jczap1`
reads as 10 px and means nothing here. The same caveat
MOVE_MATRIX.md carries.


## Does crouching or jumping change what reaches you?

Also barely. The column is W/8 either side, so a posture only
matters if it changes the silhouette's WIDTH - and crouching in
this game lowers you without narrowing you much.

Ducking changes incoming reach by between -0.9 and +4.5 px.
Crouching in MK2 is a way to go UNDER a high attack - which
3.1 measured working, 5/5 against 0/5 - not a way to make
yourself a narrower target.

Walk lanes are excluded on purpose: their extents are a union
across a nine-frame stride, so they describe the step rather
than the fighter, and would overstate every number here.
