# KAHN'S ARENA heat haze: the clouds, a scanline at a time

**Built and verified in MAME, 16 September 2026.** The first version (screen-anchored
phase) was installed from `tmp/skyhaze/mk2.zip`. The fix for the ripple speeding up
under a flip, `tmp/flip_head/skyhaze2/mk2.zip`, replaced it the same day and is what is installed.

## What it does

The sky over KAHN'S ARENA ripples with a heat haze, **one scanline at a
time**, as the old `dpytap` shimmer did. Now the ripple bends only the sky.
Kahn's staff and orb, the medallions, the pagoda roofs, the throne, the
fighters and the HUD stay still.

The dpytap version (`vshim`, 2026-08-26) was switched off because a display
register moves every plane on its scanline, and no run of rows on this stage
is background-only.

## How: the sky drawn the way the floor is drawn

`floor_code` draws a floor as one single-row DMA blit per screen line, each at
its own x. `sky_rows` (MKDISP.ASM) draws the sky the same way:

| | |
|---|---|
| Art | `data/ARNSKY.BIN`: the sky's 15 blocks (`arena6BMOD`) composited into one raw 6bpp texture, 440x127, 41,910 bytes. Generated by `tools/make_arnsky_bin.py` from `ARENA.BDB/.BDD`; Phase D re-checks it |
| Slot | `data/ARNSKY.LOD`, bank 1, `0xBB7000..0xBC1600`: the top of the free run, hard under SMTIGER |
| Layers | A blit carries one colour map and the blocks use two palettes, so the texture holds the `doom2_p` rows, then the `doomsky_p` rows. The blocks keep their own indices, and there is no new palette: `findpal` finds both live slots |
| Dlist | `.long -1,sky_rows,baklst7,worldtlx7+16,arena_sky_rows` in `dlists_arena` (BGND.ASM) |
| Each line | floor_code's queue entry: `[1:width]` at `[y:x]`, control `e002h` (6bpp, write non-zero). It is clipped at the screen edges by starting further into the row |
| Haze | +-2 px, a 32-step sine, 2 steps a line (16-line wavelength), 1 step a tick, rising. The offset is a function of the line's **world** y, so both layers of a line move together and the ripple rides with the clouds when the camera moves |
| Fallback | If `f_skyrows_off` is 1, a palette is not loaded, or the queue lacks room for the lines plus 300 cells, it draws the plain blocks. A failure costs the haze, never the sky |

Why a texture: the DMA advances its source by the blit width per row and has
no stride, so a line can only start mid-image in uncompressed art.

## Verified

`tools/arena_haze_test.lua` freezes every process and compares against
physically moving only the sky's 15 blocks. In a Liu Kang vs Shao Kahn fight:

| Gate | Result |
|---|---|
| Scene still | 0 px |
| Every line at offset 0 == the plain blocks | **0 px** |
| Every line +40 px == the sky blocks moved +40 px | **0 px** |
| Alternating lines +40 / -40, line by line | **0 wrong lines** |
| Pixels changed by moving the sky | only rows 22-106 |

Sub-Zero vs Scorpion passes the same gates.

**Camera movement** (`HAZE_CAMTEST=1`, `tmp/arena_haze/compare_camera.py`): tick is held still and the camera is moved 8 lines. The sky follows it 1:1, so after shifting back 8 rows, any extra mismatch in the haze frames is the ripple sliding. The first installed build anchored the phase to **screen** y and added **3,126 px**; the fix anchors it to world y and adds **0 px**.

**Cost**, haze on vs the plain sky, measured the same way:

| Scene | Lines a frame | Late frames | Queue overflow | Overload max | Fallback frames |
|---|---|---|---|---|---|
| Kahn fight, 360 frames | 127 on all 360 | +0 / +0 | 0 / 0 | 2 / 2 | 0 |
| Sub-Zero vs Scorpion | 127 on all 360 | +0 / +0 | 0 / 0 | 2 / 2 | 0 |
| Shang's soul escape, 1,962 arena frames | 127 | +2 / +2 | 0 / 0 | 3 / 2 | 2 |

In the soul escape the rig passes both ways, and the queue high-water is 299
cells against 213 plain, out of 500. Both fallback frames fall on gstate 7 at
the start of a round, while the stage's palettes are still loading, and never
during the escape. `tools/skyrows_cost_watch.lua` logs each one.

## What the measurements changed

1. **Bands first.** `strip_layer` banded the sky through the DMA clip, but a band
   waits for the queue to drain: about 14 scanlines of stall per band on this plane.
   15 bands stalled 238 of 288 lines and dropped the floor, throne, fighters and
   HUD off late frames. 8 bands were affordable but visibly blocky, so the user
   rejected them. Moving the blocks themselves was rejected too: they overlap at
   different heights, and separate offsets tear the clouds.
2. **A flipped block.** The first per-line build was 573 px off the plain blocks,
   all inside block (632,74). Its z is `0x4010`, and bit `0x10` is a horizontal
   flip: it is (546,74) mirrored. The runtime list order was also not the
   stage file's z order. The MAME log showed it is z with the flip bit masked,
   then y, with ties in reverse file order. The generator now follows both, and
   its proof renders the plane as the game draws it, in colour. The MAME
   offset-0 gate is the independent check.
3. **A rig race.** 8 bands during the soul escape ran it 17 frames late, and
   `tools/shang_soul_escape_test.lua` then read the next opponent before the game
   wrote it. It now judges the settled value.
4. **Faster under a flip.** Reported in play: the haze sped up when a fighter flipped. The vertical camera chases a high fighter (`scrl6`, BGND.ASM), so the sky slides down the screen through a screen-anchored ripple. The phase now uses world y. The fixed build was packaged from a clean git worktree (HEAD plus only the sky-haze change). Its program ROM was swapped into the verified package, whose 18 other chips are byte-identical, because the shared tree held two other sessions' in-progress features and its Cage IMGs are skip-worktree.

## 19 September 2026: aimed at the top of the fire, and made to boil

Asked for: "just focus on the top of the clouds and make the heat shimmer feel
like looking at an oil spot on the road, or the desert." What changed:

| | Before | Now |
|---|---|---|
| Where | every row of the plane, same strength | a **band**: the stage record's envelope (`+040`, was reserved) gives a tier per world row. `arena_sky_haze` (BGND.ASM): full on rows 43-52 (the fire's topmost edge), thinner to 60, still elsewhere |
| Wave | one sine, +-2, 16-row wavelength, rising | two sines summed: coarse +-2 over 8 rows rising 1/4 row a tick, fine +-1 over 5 1/3 rows rising 1/2 row a tick. Different wavelengths AND speeds, so it boils instead of rolling |
| Fade | none | tiers are a mask of the two waves (1 coarse, 2 fine, 3 both), so the fringes drop to the fine wave only. No multiply |
| Edge | wave centred on 0 | centred `SKR_AMP` (3) px clear of whichever edge is short (`skr_dxc`), then clamped to what still covers the raster |

**Why the band is where it is.** It was placed by what is ON SCREEN, not by the texture.
The arena's towers hide most of the plane. Shifting the whole sky and counting the moved
pixels per row (rows_0 vs rows_p) shows the fire is visible on world rows 43-106, and its
top edge, where the fire meets the purple, is at 43-50. The first try put the band at 60-104
from the texture alone, which put it in the middle of the visible fire. The loose cloud
above 43 is left still, because shifting it whole reads as a cloud sliding.

**An edge bug the old build had.** The probe (`worldtlx7`) shows the sky plane sitting AT
its scroll limit (x0 = 0) for the whole fight, so every swing right on the old +-2 wave tore
up to 2 px of empty page off the left edge. The wave now rests 3 px left and swings -6..0.
That is a still nudge of the backmost plane, which nobody can see.

**Measured** (Sub-Zero vs Scorpion, per-row shift of sky pixels only, 32 frames): rows 47-68
swing -6..0, 43-46 and 69-76 -5..-1, 77-84 -4..-2, everything else a steady -3. No row ever
goes past 0. The frozen gates still pass: `compare_rows.py` ALL PASS. Cost is unchanged at
127 lines/frame, fallback +0, late +0, overload max 2, deep_dmaq 260. GIFs:
`tmp/arena_haze/haze_top.gif`, `haze_top_zoom.gif`.

**Second pass, same day:** "still too much cloud, really focus on the topmost area". The band went from 47-68 (fading out by 84) to 43-52 (fading out by 60). Measured: only rows 43-60 move, every other row holds still, and the gates are ALL PASS at the same cost.

**Third pass: slower.** A new knob, `SKR_TSH` (MKDISP.ASM), shifts the haze's clock right, and the default 1 is half speed: the waves now rise 1/8 and 1/4 of a row a tick. Set 0 for the old speed or 2 for a quarter of it. Measured: the band pixels that change from one frame to the next fell from 30,639 to 17,759 over the same 32 frames, and the gates are ALL PASS at the same cost.

Tuning is data: the tier rows in `arena_sky_haze`, the amplitudes in `skr_wave1`/`skr_wave2`,
and `SKR_AMP` if the wave gets wider.

## 4 October 2026: the OTHER two clouds

Reported in play: "kahns arena has a few clouds that dont have the wavy edge to
them ... one behind the life bar, and one more subtle at the bottom of the
upper screen". Both were real, and both were the envelope's doing - the band
was 38-60, so everything above and below it was still by construction.

**This plane holds three separate things, not one.** Composited and measured
per world row (`tools/stage_preview.py` plus the other planes' occlusion, all
three camera stops):

| world rows | what | where it is on screen |
|---|---|---|
| 22-45 | two LOOSE CLOUDS in the black sky | behind the life bars; visible in the RIGHT half only - the left half is 0 px until row 36 |
| 36-60 | the big LEFT FIRE's topmost edge | between the towers, the band that was already hazed |
| 74-96 | the distant RIDGE on the right | inside the purple band, through the pagoda arches - the "subtle" one |

The ridge's silhouette undulates between rows 74 and 88 (per-column top edge of
the front layer), which is why the band has to span that and not just sit on an
average.

`arena_sky_haze` now runs the plane's **whole** 22-106:

```
22-23    2    fine only: the loose cloud's thin tip
24-37    3    both: the two loose clouds
38-42    2    fine only: the fringe above the fire   (unchanged)
43-52    3    both: the fire's topmost edge          (unchanged)
53-56    1    coarse only                            (unchanged)
57-73    2    fine only: the fire's BODY between the two edges
74-85    3    both: the ridge's silhouette
86-89    1    coarse only
90-106   2    fine only, down to the bottom of the plane
```

The three bands that were tuned on 19 September are untouched, so the fire's
hot edge looks exactly as it did.

**"Shifted whole, it reads as a cloud SLIDING" was wrong, and that is why the
loose clouds were left out in the first place.** The coarse wave is 8 world
rows and the fine one 5 1/3, so a cloud 20 rows tall gets two and a half cycles
of it and BENDS. Measured across the cloud at one tick: 0, -1, 0, 0, 0, +2, +2,
+3, +3, +3, +2, +2 - an S, not a translation.

### A still region is only invisible at the OUTSIDE of the haze

The first cut of this change covered 22-93 and left 61-71 (between the fire's
edge and the ridge) and 94-106 (under the ridge) at tier 0, on the same
reasoning the 19 September pass used: no silhouette lives in those rows, so
there is nothing for a wobble to bend. That was wrong, and it was reported
within the hour - "theres a slight gap in the middle cloud now all the way to
the left side of the screen that does nothing".

**The body of a fire does not need an edge to look dead.** Rows 61-71 carry
106-142 px of visible fire on the LEFT half, and with 43-60 moving above them
and 72-93 moving below, an 11-row strip of it stood motionless between two
strips that did not. The eye reads that as a band across the screen. The same
would have been true of 94-106 under the ridge.

So the rule the 19 September pass found - aim the full wave at the edges - is
kept, and one more is added on top of it: **nothing visible is ever completely
still.** The bodies get the fine wave alone (+-1 px), which is enough that they
are never dead and small enough that they never compete with the edges. The
only tier 0 left is outside the texture altogether.

**Which rows have visible sky is MEASURED, not read off the texture**, and it
has to be: the towers cover most of this plane and the HUD covers the top.
Move the 15 sky blocks +-40 px with the scene frozen and count the pixels that
change - the rig's own `shift_p` / `shift_m` shots. Every row of 22-106 has
visible sky in it; row 28 alone is wholly behind the "00 WINS" text.

**Measured after the fix** (`HAZE_BAND=1`): rows 61-72, which moved 0 px
before, now move 58-267; every row of 22-106 moves except 27-31, which are
behind the HUD; and nothing outside 22-106 moves at all.

**Cost is unchanged**, which it has to be: the envelope only decides what
offset a line gets, never how many lines are queued. Sub-Zero vs Scorpion, 360
frames: 127 lines on every frame, fallback +0, `dmaq_late` +0, `dmaq_over` +0,
overload max 2, `deep_dmaq` 260 cells - the same numbers as the narrow band.
The frozen gates still read ALL PASS.

### Reading the envelope back off the screen

`HAZE_BAND=1` is the mode the FREEZE gates could not cover: they pin the offset
by hand (`f_skyrows_off` 2 and 3), so they prove the line machinery and say
nothing about the envelope. It freezes every process and leaves the haze LIVE -
`tick` still advances under a frozen scene, so the only thing that moves is the
sky - and takes 16 consecutive shots.

```
HAZE_BAND=1 HAZE_LOG=<run>/haze.log mame ... -autoboot_script tools/arena_haze_test.lua
python tools/arena_haze_band_check.py <run>
```

**The still rows are the reference.** The plain blocks are no use as one: the
whole plane rests `SKR_AMP` px left of its scroll limit, so a still row under
the live haze is not where the ordinary draw puts it and every row of the sky
would read as moved. A row identical in all 16 shots is one the envelope left
alone.

**The sharp gate is the negative one** - no row OUTSIDE the envelope may move -
because that is the half a covered row cannot fake. A row inside the band that
never moved is reported, not failed: the towers cover most of this plane and
the HUD covers the top, and the right-hand cloud's rows 27-31 sit squarely
under the "00 WINS" text. What is required of each BAND is that one of its rows
moved. Crossed against the old 38-60 table with the new ROM running, the check
fails 33 rows, so it discriminates.

## Cost, measured with the display meter (2026-10-12)

Same ROM, same fight, haze on vs `f_skyrows_off=1`: the haze cost ~90 lines of
the display interrupt's CPU and ~100 of the blitter a frame, and left KAHN'S
ARENA 17 lines of headroom - the tightest stage in the game by 37
(doc/PERFORMANCE.md 3c).  The line loop now keeps its per-frame constants in
b0-b5 and reads the haze from a 16-row table (`skr_dxt`) - both waves repeat
every 16 world rows - which took 17 lines off both the mean and the worst
frame (headroom 34), pixel-identical by every gate above.
